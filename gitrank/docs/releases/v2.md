# GitRank V2 Release Notes

Status: implementation track in progress, not a production launch approval.

These notes document what V2 removes from the V1 limitation set and what still
requires live environment proof before production deployment.

## Removed V1 Limitations

- Production frontend routes no longer depend on mock API functions, the old
  authenticated mock dataset, or `?demo=` preview routes.
- Dashboard, quest, PR report, profile, leaderboard, badge, contribution, and
  settings views read live BFF contracts.
- Public PR reports read persisted PR, analysis, score-event, file, review, and
  badge evidence instead of frontend mock report data.
- Direct PR sync stores bounded changed-file metadata, derived file features,
  and public patch excerpts without storing full repository files.
- User sync includes bounded authored-PR discovery for public repositories where
  GitHub search exposes contributions, not only repositories owned by the user.
- PR analyzer responses can now persist deterministic analysis artifacts against
  synced PR evidence and return `analysis_id`/`pull_request_id` provenance.
- Scheduler analysis jobs can now execute persisted PR analysis through
  pr-analyzer before score replay.
- Score replay can deterministically recompute from persisted PR, analysis,
  file, review, and repository evidence and can verify replay without mutating
  state.
- Scheduler score replay jobs now call the real scoring engine replay endpoint
  and return replay-run provenance through the worker execution response.
- Profile refresh jobs now call the real profile-service snapshot rebuild route
  and return profile-snapshot provenance through the worker execution response.
- Bounded PR grading pipeline jobs now chain direct PR sync, persisted analysis,
  score replay, profile refresh, and live PR-report verification for a known
  user and PR.
- Profile score history now exposes score-event, formula-version, PR, analysis,
  and missing-evidence state.
- Leaderboard rows expose profile-snapshot provenance, score version, source
  watermark, and missing rank-ledger evidence.
- Skill claims expose evidence source, confidence, and stale or partial states.
- PR reports expose incomplete, stale, rate-limited, deterministic-only, and
  AI-fallback evidence states.
- The frontend no-mock release gate fails on production mock imports, missing
  critical OpenAPI paths, and dropped critical worker/profile smoke coverage.
- The V2 staging seed uses synthetic GitHub-like evidence through persistence
  and real service APIs instead of frontend mock functions.

## Still Out Of Scope Or Not Yet Proven

- Private repository ingestion and private-code AI analysis remain out of scope.
- GitHub OAuth remains the V1 identity path; GitHub App installation support is
  still required for organization-scale inventory, webhooks, and more reliable
  repository access.
- Dedicated PR-report materialization/backfill storage is still pending; the
  current one-shot grading path verifies the live report read model instead of
  writing a separate materialized report row.
- Backfill jobs for historical PR reports, quest rewards, season rankings, and
  badge history still need implementation; score replay and profile refresh are
  the first real executable scoring/profile backfill jobs.
- Quest assignment, progress, completion, and reward writers still need to
  replace profile-derived quest recommendations before quest rewards are fully
  evidence-backed.
- Leaderboard season snapshots and rank movement ledgers still need dedicated
  persistence before ranks are fully materialized season results.
- Production observability assets exist, but dashboards and alerts still need
  live traffic verification.
- Live GitHub repository controls, dependency graph, Dependabot alerts, branch
  protection or rulesets, and required checks still need to be applied and
  verified against the actual repository.
- Kubernetes manifests remain provider-neutral until real secrets, TLS, ingress,
  registry, managed PostgreSQL, managed Redis, and autoscaling are wired for the
  target environment.
- Staging rollback and restore drills must be executed and recorded before
  production release approval.

## Required Gates Before Production

- `make test`
- `make vet`
- `make test-critical-path-flows`
- `make verify-v2-no-mock-release-gate`
- `make verify-v2-staging-seed`
- `make verify-observability-manifests`
- `make verify-rollback-procedure`
- `make verify-secret-policy`
- live GitHub repository-control verification
- staging rollback and restore evidence record
