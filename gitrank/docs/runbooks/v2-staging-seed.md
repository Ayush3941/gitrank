# V2 Staging Seed Runbook

Use this runbook to create a synthetic V2 user in staging without frontend mock
data.

The seed inserts only GitHub-like evidence and deterministic analysis records
into PostgreSQL:

- user and linked GitHub account
- public repository
- merged pull request
- bounded changed-file metadata and public diff excerpts
- review and review-comment evidence
- deterministic `contribution_analyses` record
- profile visibility settings

The seed does not insert score events, replay runs, score snapshots, badge
awards, or profile snapshots. Those artifacts must be generated by real service
APIs.

## Prerequisites

- `DATABASE_URL` points to the target staging database.
- `SCORING_ENGINE_BASE_URL` points to the running scoring service.
- `PROFILE_SERVICE_BASE_URL`, `API_GATEWAY_BASE_URL`, or `GITRANK_API_BASE_URL`
  points to a read API that exposes public profile and PR-report routes.
- The target environment is staging.
- The operator has confirmed the run with `ALLOW_V2_STAGING_SEED=1`.

## Run

```sh
cd gitrank
GITRANK_ENV=staging \
ALLOW_V2_STAGING_SEED=1 \
DATABASE_URL="postgres://..." \
SCORING_ENGINE_BASE_URL="https://scoring.internal.example" \
API_GATEWAY_BASE_URL="https://api.staging.example" \
./scripts/seed_v2_staging.sh
```

Set `RUN_MIGRATIONS=1` only when the staging migration process for that
environment allows the seed operator to apply pending migrations before seeding.

For a local rehearsal against development services, add:

```sh
ALLOW_V2_STAGING_SEED_IN_DEVELOPMENT=1
```

## Verification

The script verifies:

- scoring replay returns a persisted snapshot and event count
- scoring event readback contains the seeded repository
- public profile readback contains `v2-staging`
- PR battle-report readback exposes `evidence_state`

To verify the SQL seed shape without running services:

```sh
cd gitrank
make verify-v2-staging-seed
```

That check proves the seed inserts raw evidence but does not precompute score or
profile artifacts.
